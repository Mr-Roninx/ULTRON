1. **Clone repository & enter directory**:
   ```bash
   cd "d:/Work Space/Project/Ultron"
   ```

2. **Verify Node.js environment**:
   - Node.js version: `>= 20.0.0`
   - Package manager: `npm`

3. **Verify Environment Variables (`.env`)**:

## 2. Quickstart: Running the System

### Step 1: Start the Backend API Server
```bash
npm run dev
```
- Server starts on `http://localhost:3001`
- SQLite database initializes automatically with schema migrations (`ultron.db`).

### Step 2: Start the Next.js Frontend Dashboard
In a second terminal:
```bash
cd frontend
npm run dev
```
- Dashboard opens on `http://localhost:3000`.

### Step 3: Seed Synthetic Scenario Data
```bash
npm run seed
```
- Populates the database with 50+ diverse failed payment scenarios (soft declines, liquidity drops, gateway timeouts, fraud blocks, attempt fatigue).

## 3. Live Demonstration Walkthrough

### Scenario A: Autonomous Recovery Mission (The 13-Stage Journey)
1. Open the UI at `http://localhost:3000`.
2. Navigate to the **AI Agent Control Center** tab.
3. In the **Mission Launcher**, select opportunity `synth_02_insufficient_funds_att1`.
4. Click **Launch Mission**.
5. Observe the live progression:
   $$\text{Observe} \to \text{Investigate} \to \text{Reason} \to \text{Plan} \to \text{Proposal} \to \text{Economics} \to \text{Market} \to \text{Authority} \to \text{Complete}$$
6. Inspect the **Persisted Telemetry Trace**:
   - Step #1 [`OBSERVE`]: Reads decline parameters.
   - Step #2 [`INVESTIGATE`]: Executes `get_payment_attempts` and `get_customer_history`.
   - Step #3 [`DIAGNOSE`]: NVIDIA NIM classifies transient liquidity drop.
   - Step #4 [`PLAN`]: Formulates assumption-backed recovery plan.
   - Step #5 [`PROPOSE`]: Submits recovery proposal with bounded modifier ($\Delta P = +0.039$).
   - Step #6 [`WAIT_AUTHORITY`]: Evaluates deterministic compliance gate.
   - **Privacy Verification**: Verify that private raw chain-of-thought is suppressed; only structured observations and public actions are rendered.

### Scenario B: Action Authority Compliance Veto (Economic vs. Compliance Separation)
1. Select a fraudulent hard decline scenario: `synth_05_stolen_card_att1`.
2. Launch an autonomous mission.
3. Observe that even if an economic case exists, the deterministic **Action Authority Gate** independently intercepts and issues a **`BLOCKED`** compliance veto due to hard decline code `card_stolen`.
4. **Safety Proof**: Zero payment links created; financial write strictly rejected.

### Scenario C: Dynamic Environmental Degradation & Replanning

